# Этап 010 — аудит

Дата: 03.11.2026. Проверенная исходная ревизия: `06f5d28819017abc237a93323cd10daaf7bcdeb6`.

## Подтверждённые причины

| Дефект | Наблюдение | Изменение / остаток |
|---|---|---|
| P0-1, разбор вопроса | `_question_attributes()` не разбирал контрольный составной вопрос; пустой набор слотов приводил к неопределённой оценке. | `QuestionAnalyzer` создаёт слоты по морфологическим леммам и маркерам отношений. Для неизвестного формата вопроса теперь отдельный `unsupported`; это не универсальный синтаксический анализатор. |
| P0-2, извлечение | Старый `_extract_attribute_facts()` был привязан к цифрам и узким формам ответа. | Добавлены `ExtractedFact` и `ClaimExtractor`: числа словами, единицы, границы, даты, форматы, локальные условия и offsets цитаты. Это ограниченные правила; сложные отрицания и межфразовые отношения не поддерживаются. |
| P0-3, версии | Даты и маркеры поправок не задавали явную операцию и цель. | `VersionResolver` представляет частичную замену/дополнение/отмену как операции и требует family, точного названия либо узкого совместимого legacy-доказательства. При неизвестной применимости ответ закрывается. Полный парсер пунктов регламентов и всех видов отмен ещё не реализован. |
| P0-4, достаточность | `sufficient` не гарантировал аудит связанных редакций. | В `revision_links` индексируются документы внутри family и поправки с явной ссылкой на целевой заголовок. Полнота ограниченного снимка редакций становится обязательным условием структурного ответа. Неизвестные и не связанные индексом поправки нельзя считать отсутствующими. |
| P0-5, проверка | Повторный вызов извлекателя не был независимым смысловым судом. | `EvidenceVerifier` отдельно сверяет точную цитату, digest, offsets, идентификатор источника, применимость и полный состав ответа. Логическое следование не объявляется проверенным: семантической модели/NLI нет. |
| P1-1/2, редакции | BM25-ограничение и SQL-фильтр `max date per family` могли удалить старую базу или отдельную поправку. | Поиск снимка редакций не применяет `as_of` до разрешения; межсемейные связи индексируются явно. При слишком большом числе фрагментов каталог отмечается неполным. |
| P1-3, новые факты | Идентификатор атрибута не отличал новое значение, дату, источник или условие. | Контроллер сравнивает SHA-256 сигнатуры typed claim, включая значение, оператор, единицу, условие, редакцию, происхождение и span. Остановка по отсутствию новых утверждений не используется. |
| P1-4, два поиска | `/research` смешивал поиск контроллера с отдельным поиском для показа. | `/research` теперь отдаёт фрагменты из единого trace-контракта; цитаты UI связываются по `evidence_id`. Полное время включает предварительный разбор и поиск. |
| P1-5, даты | Дата вопроса не согласовывалась с фильтром. | Явная одна дата становится `as_of`; расхождение с фильтром или несколько дат приводят к отказу с указанием конфликта. |

## Исправления браузерной совместимости

Реальный запуск Pyodide обнаружил, что SQLite WASM connection не поддерживает `executemany`; индекс связей теперь записывается через `execute`. E2E также выявил, что ссылка на citation пыталась найти фрагмент по равенству короткой цитаты и полного текста chunk; UI теперь связывает источник по стабильному evidence ID.

## Ограничение аудита

Точное содержимое внешнего «Полевого корпуса речи» в checkout отсутствовало. Проверка воспроизводит опубликованные эталонные значения на отдельном авторском синтетическом корпусе, открыто помеченном как синтетический. Это не независимый аудит и не эмпирическое подтверждение качества на реальных регламентах.
