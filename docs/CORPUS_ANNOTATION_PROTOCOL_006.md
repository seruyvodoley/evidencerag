# Протокол источников и ручной разметки для этапа 006

## Кандидат на пилотный реальный корпус

Рассмотрены официальные versioned-разделы Python «What’s New»:

- [Python 3.12](https://docs.python.org/3.12/whatsnew/3.12.html)
- [Python 3.13](https://docs.python.org/3.13/whatsnew/3.13.html)
- [История и лицензия Python](https://docs.python.org/3/license.html)

Страницы указывают версии документации 3.12.16 и 3.13.18 на момент просмотра 30.10.2026; это версии документации, а не замена исходным release tags. Официальная страница лицензии указывает PSF License Version 2 для документации и дополнительно Zero-Clause BSD для примеров, рецептов и другого кода в документации. Перед распространением снимков нужно сохранить лицензионное уведомление/условия и проверить отдельно сторонние материалы, перечисленные внутри документации. Это фиксация первичных источников, не юридическое заключение.

Источники не загружены в корпус и не размечены. Причина: сначала нужен контролируемый scope (одна тема изменений, неизменяемые снимки и экспертная проверка), чтобы не представить автоматически собранные QA-пары как независимую истину. В текущих экспериментах эти страницы не использовались.

## Протокол импорта

На каждую редакцию сохранять:

- исходный URL, versioned path, название, издателя, дату/время получения UTC и HTTP `Last-Modified`, если доступен;
- точные release/version labels и отдельные редакции в одном family;
- оригинальный source SHA-256, формат/объём, условия лицензии и уведомление об авторских правах;
- SHA-256 извлечённого текста, parser/chunker revision, параметры разбиения и таблицу соответствия фрагмента заголовку/якорю источника;
- статус происхождения: официальный первичный источник, зеркало или пользовательский материал.

Снимки неизменяемы: обновление сайта создаёт новую версию данных и новые хеши. Историю изменений не склеивать в одну «последнюю» редакцию. Все редакции семейства должны находиться в одном split.

## Поля разметки каждого вопроса

`question_id`, `document_family`, `question`, `as_of`, `requested_version`, `gold_status` (`sufficient`, `insufficient`, `conflicting`, `uncertain`), `gold_answer` или причина отказа, `required_evidence_ids`, минимальный набор достаточных групп доказательств, `applicable_revision_ids`, `conflicting_claims`, `gap_types`, источник каждого label, annotator IDs, заметка о неоднозначности и adjudication status.

Один и тот же вопрос может требовать несколько фрагментов и несколько редакций. Межредакционное изменение само по себе не является конфликтом; конфликт относится к одновременно применимым несовместимым утверждениям. Если момент действия или область применения неясны в самом источнике, label должен быть `uncertain`, а не выбранная annotator-ом догадка.

## Двойная разметка и арбитраж

1. Два эксперта размечают вопрос независимо и не видят labels друг друга или ответов оцениваемых моделей.
2. До основной разметки проводится короткая калибровочная сессия на отдельной группе вопросов; правила меняются только до фиксации test-набора.
3. Сверяются status, необходимые источники/фрагменты, версия применимости и причина конфликта/отказа. Разногласия сохраняются как данные, затем разрешаются третьим reviewer с письменным обоснованием.
4. Публикуются число вопросов и семейств, соглашение по каждому полю и таблица разногласий. Cohen’s kappa/другой коэффициент приводится только для корректно определённой категориальной метки и достаточного размера; agreement по множествам evidence IDs считается отдельно.
5. Автоматическая генерация вопросов или labels используется для предложений annotator-ам, но не называется экспертной gold-разметкой.

## Разделение и оценка

Сначала группировать данные по семействам источника/версий, затем закреплять группы за train/dev/test; никакая редакция одного family не пересекает split. Не подбирать параметры на test. Для сравнения методов использовать одинаковые вопросы, разрешённые документы и бюджет. Считать парные показатели по вопросу; при нескольких вопросах внутри семейства применять family-level кластеризацию/агрегацию. Для каждого показателя публиковать знаменатель, число случаев и причины `null`.
