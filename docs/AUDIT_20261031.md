# Технический и методологический аудит

Дата: 31.10.2026. Аудит выполнен по актуальным исходникам, датасету, тестам и трем сохранённым историческим прогонам. `pytest` до изменений прошёл: 32 теста.

## Критические находки

1. **False Abstention=1.0 был неправильно определён.** `evaluate()` считал ответом только демонстрационное authored `formal_rule`; все остальные ответы в retrieval-only запуске объявлялись отказом. Продукт не выдавал свободные ответы, поэтому эта цифра не измеряла отказ answerer. `answer_correctness`, `false_abstention`, `unsupported_answer_rate` и semantic sufficiency теперь остаются `null` без генератора и judge.
2. **Три датированных эталона не имели gold answer/required source.** Они стояли как `sufficient=true`, но не участвовали в evidence recall. Добавлены известные значения и обязательные строки редакций 2025.
3. **Редакционная смена называлась конфликтом.** Любые разные `key: value` одного family сваливались в одно `potential_conflict`, даже если значения из разных датированных редакций. К тому же поиск мог показать изменение другого поля, не относящегося к вопросу. Теперь field signals ограничены точными терминами поля из запроса; dated edition changes, same-edition disagreements и неизвестная применимость раздельны.
4. **Аналитическая схема baseline/ablation была неверной.** `without_versions` запускал тот же код, что adaptive, поэтому абляции не происходило; adaptive сам расширял поиск по покрытию слов и не был top-k по score. Runner теперь предоставляет 4 именованные контроллера через один интерфейс; score-gap BM25 отдельно помечен эвристикой, не репликацией Adaptive-k. Абляции отключают конкретные доступные компоненты.
5. **Sufficiency-guided baseline отсутствует по существу.** Интерфейс judge и trace готовы, но в штатном run судьи нет; решение `unknown`, и поиск ограниченно расширяется. Ключевые слова не выдаются за достаточность. Answerer, semantic QA, faithfulness и сравнение с сильными моделями остаются не измеренными.
6. **Синтетические fixtures не являются научным бенчмарком.** Всего 63 авторских случая и 3 независимых test-кластера; для статистических выводов этого недостаточно. Run-004 не публикует bootstrap CI или p-values.

## Исправления этой итерации

- `apps/api/evidencerag/retrieval.py`: релевантность field signals ограничена запросом; известные dated changes и same-edition conflicts различаются; добавлены контроллерные actions и stable evidence/provenance IDs; judge `unknown` и bounded gap items поддержаны без активации внешней модели.
- `apps/api/evidencerag/main.py`: compare endpoint возвращает dated differences отдельно; health указывает `lexical-controller-v2` и отсутствие semantic judge.
- `packages/research/runner.py`: единый fixed/adaptive/sufficiency/proposed интерфейс, фиксированные равные upper budgets, content-derived IDs, подробные traces, source/input/environment hashes, nullable неподдерживаемые метрики.
- `datasets/evaluation/cases.json`: явные expected-resolution labels, кластеры по корпусу и исправленные датированные gold strings.
- `apps/web/src/App.svelte`: separate labels для истории редакций и конфликта внутри одной редакции; объяснение ограничения score-gap и отсутствия семантической проверки.

Никакой SQL schema migration не требуется. Контракт API расширен дополнительными полями; имеющиеся поле `conflicts` теперь семантически уже и содержит only same-edition literal disagreement.

## Не охвачено

Нет независимого реального benchmark, двойной экспертной разметки, семантического judge/answerer, partial-amendment model, воспроизводимых экспериментов S2G/Adaptive-k/TimelyRAG/ProStruct-RAG, проверки подлинности источника, OCR или полного перебора prompt-injection вариантов.
