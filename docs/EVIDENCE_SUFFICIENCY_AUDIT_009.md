# Аудит достаточности доказательств — этап 009

Обновлено 03.11.2026. Это аудит реализации и авторские синтетические регрессии. Он не оценивает точность на независимом корпусе.

## Причина наблюдавшегося отказа

По приложенному описанию пользователя система показала `evidence_uncertain`, `assessment_uncertain_without_actionable_gap`, `expand_top_k` и `stop_no_new_evidence_claims`. Эти записи получены со скриншотов; исходные пользовательские файлы и полный экспорт этой трассы в checkout отсутствуют, поэтому исходный прогон нельзя независимо повторить.

Исходники подтверждают фундаментальную причину. В `apps/api/evidencerag/research_rag.py`:

- `UnavailableSemanticEvaluator.evaluate` всегда возвращает `uncertain`, потому что лексический retrieval не проверяет смысл.
- `FormalRuleEvaluator.evaluate` принимает только точное совпадение полного вопроса с заранее авторизованным правилом, потом ищет каждый заранее указанный `exact_quote` с ограничениями версии и даты. Общего выделения фактов и атрибутов у него не было.
- `UnavailableAnswerGenerator` отказывает. `LiteralExtractAnswerGenerator` возвращает лишь дословные цитаты и не умеет свести несколько значений в короткий ответ. `validate_answer` намеренно отклонял перефразирование без semantic judge.
- Контроллер мог расширять top-k без структурированного списка запрошенных фактов; если новая выдача не добавляла claim ID, он завершал цикл.
- `EvidenceStoreBackend` применял только один `family` filter. Поправка в отдельной группе документов не попадала в контекст, если пользователь выбрал группу основной редакции.

Следовательно, гипотеза о чрезмерно узком `authored_exact_quote_rule` подтверждается исходниками. При этом полный исходный тестовый прогон в Samsung Internet мы не воспроизвели на тех же пользовательских файлах; создана реплика сценария из текста задания.

## Компоненты и пределы проверки

| Компонент | До этапа | Изменение этапа | Остаток |
|---|---|---|---|
| Retrieval | Workspace-scoped SQLite FTS5/BM25, русский `terms()`; лексический сигнал | Кандидаты поправок ищутся в том же workspace без ограничения основной группой; только датированный текст с маркером изменения и ссылкой на дату редакции. Выбранные controller-фрагменты включаются в UI | Лексический recall может пропустить поправку; similarity названий не считается связью |
| Chunk selection | Задаётся top-k, исследовательский UI ставил 1 | Для browser EvidenceRAG используется небольшой начальный top-k=5, чтобы полная редакция и поправка могли попасть в один контекст | При больших/разбитых документах может потребоваться targeted retrieval; бюджет ограничен |
| Нормализация вопроса | Русская морфология для FTS; совпадение терминов | Явные синтаксические запросы `сколько N`, `в каком виде`, ограниченный набор подписанных параметров | Не является универсальным разбором вопроса и не знает произвольные отношения |
| Sufficiency | Только authored exact rule или `uncertain` | `StructuredClaimEvaluator`: все извлечённые атрибуты должны получить датированный факт; пропуски перечисляются, одинаково применимые разные значения дают conflict | Это локальные правила/regex, не NLI, entailment или семантический judge |
| Claim extraction | Не было общего этапа | число + запрошенное существительное; длительность + единица; форма сдачи рядом с действием; allowlist подписанных key:value полей | Ограниченное покрытие; отрицания и сложные придаточные не моделируются полноценно |
| Версии и поправки | Только authored ограничения версии; метаданные полной редакции | Последняя датированная основная редакция в группе плюс частичная поправка, если текст ссылается на дату её начала и содержит маркер изменения; меняется только извлечённый атрибут | Не моделируются отмена документа, полная замена поправкой, приоритет разделов, ретроактивность и юридическая сила источника |
| Conflict detection | Формальные конфликты из evaluator | Два разных значения на одной применимой дате/для одной связанной редакции не выбираются произвольно | Не доказывает логическую несовместимость фраз; конфликт означает совпавший структурированный атрибут |
| Adaptive controller | Неопределённость могла вести к `expand_top_k` | Структурированный evaluator выдаёт конкретные missing attributes; query сохраняется в трассе; завершение при достаточности и конфликтах; бюджеты сохранены | Новые chunks без новых supported claims останавливают цикл; сложное рассуждение о поисковых запросах отсутствует |
| Answer construction | Недоступен либо только literal extract | `StructuredFactAnswerGenerator` строит строку только из подтверждённых атрибутов; у каждого claim есть quote, ID, редакция и дата | Нет свободного обобщения, пояснения или semantic paraphrase |
| Citations | ID и verbatim quote проверялись строго | Для structured claim ID должен существовать, quote должен равняться исходному фрагменту; тот же извлекатель должен повторно найти тот же атрибут/value в цитате | Это механическая проверка связи, не независимое подтверждение истинности/логического следования |

## Безопасность и локальность

- Код выполняется через уже встроенный browser-local Pyodide Worker и SQLite WASM; запросы не отправляются в FastAPI/API или к модели.
- FTS supplement search использует переданный workspace ID; document/chunk lookup в local API также ограничен этим workspace.
- Загруженный текст трактуется как данные; Python `eval`/динамический импорт из документов и HTML-вставка документов не добавлялись.
- Desktop/mobile E2E проверяют отсутствие внешних origin-запросов и `/api/*`.
- Тяжёлая модель не скачивается и не запускается автоматически. Уведомления о согласии для внешней модели не требуются, так как её здесь нет.
- Browser E2E — Chromium desktop и iPhone viewport emulation; реальный Samsung Internet, Safari, Firefox, CSP/security headers хостинга и физические устройства этим этапом не проверены.

- `apps/api/evidencerag/research_rag.py`: `StructuredClaimEvaluator`, `_question_attributes`, `_extract_attribute_facts`, `_referenced_dates`, `StructuredFactAnswerGenerator`, citation validation, `EvidenceStoreBackend` и итоговая схема trace.
- `apps/web/src/local-api.py`: выбор authored rule или структурированных правил и включение выбранных первоисточников в browser response.

- `tests/test_stage009_structured_answers.py`, `apps/web/e2e/answer-generation-009.spec.ts`: автоматизированные проверки.
- `experiments/stage009/`: авторская fixture, воспроизводимый SQLite/FTS runner, trace и измеренный результат.
