# Архитектура

Frontend: Svelte 5, TypeScript, Vite, статическая production-сборка. Выбран Svelte + Vite вместо SvelteKit: сервису не нужен отдельный SSR-процесс; готовые файлы раздаёт FastAPI. Это сохраняет предпочтительный язык и библиотеку интерфейса, снижая расход RAM.

Backend: Python 3.12, FastAPI; один Uvicorn worker. SQLite в WAL-режиме, FTS5 BM25, нормализация русского pymorphy3 с ограниченным LRU-кэшем отдельных слов. GPU и векторная база не требуются.

- `apps/api/evidencerag/parser.py`: PDF/DOCX/TXT/MD; отдельный процесс, 15 секунд, CPU 12 секунд и адресное пространство 384 MiB на Linux.
- `store.py`: пространства, реестр версий, оригиналы BLOB, фрагменты и FTS-триггеры. Все операции ограничены workspace. Хеш SHA-256 оригинала.
- `retrieval.py`: нормализация, контроллер, анализ недостающих терминов, сравнение явно подписанных полей, политика вывода.
- `llm.py`: отключённый по умолчанию адаптер совместимого API; доступен только в коде частных экспериментов.
- `main.py`: строгие API-схемы, cookie, лимиты тела запроса, CSRF, загрузка/удаление/поиск/diff и раздача интерфейса.
- `packages/research/runner.py`: независимый offline CLI; не импортирует FastAPI, использует только parser/store/retrieval.

Оригиналы и текст хранятся в одной SQLite для атомарного каскадного удаления. До 20 файлов/40 МБ на пространство, всего до 400 МБ оригиналов. База с индексом и свободными страницами может быть больше этой суммы; нужен мониторинг свободного места. Рабочие пространства живут 24 часа, очистка при запуске и раз в минуту. Это не шифрованный сейф.

Версия — строка владельца, дата — дата применимости, а не время загрузки. `as_of` выбирает max(date) в каждой группе; модель предполагает полные снимки редакций и не реализует наследование отдельных поправок. Новые retrieval-модули могут заменить FTS-поиск через интерфейс store.search; семантический оценщик должен быть отдельным компонентом.
