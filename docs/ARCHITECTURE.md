# Архитектура

Frontend: Svelte 5, TypeScript, Vite, статическая production-сборка. Выбран Svelte + Vite вместо SvelteKit: сервису не нужен отдельный SSR-процесс; готовые файлы раздаёт FastAPI. Это сохраняет предпочтительный язык и библиотеку интерфейса, снижая расход RAM.

Backend: Python 3.12, FastAPI; один Uvicorn worker. SQLite в WAL-режиме, FTS5 BM25, нормализация русского pymorphy3 с ограниченным LRU-кэшем отдельных слов. GPU и векторная база не требуются.

- `apps/api/evidencerag/parser.py`: PDF/DOCX/TXT/MD; отдельный процесс, 15 секунд, CPU 12 секунд и адресное пространство 384 MiB на Linux.
- `store.py`: пространства, реестр версий, оригиналы BLOB, фрагменты и FTS-триггеры. Все операции ограничены workspace. Хеш SHA-256 оригинала.
- `retrieval.py`: нормализация, bounded controller, стабильные IDs evidence, анализ явно подписанных полей и политика результата. Датированные различия и same-edition literal disagreement возвращаются отдельно.
- `llm.py`: отключённый по умолчанию адаптер совместимого API; доступен только в коде частных экспериментов.
- `main.py`: строгие API-схемы, cookie, лимиты тела запроса, CSRF, загрузка/удаление/поиск/diff и раздача интерфейса.
- `packages/research/runner.py`: offline CLI без запуска FastAPI; переиспользует parser/store/retrieval. Единый запуск включает fixed-k, score-gap adaptive-k, sufficiency controller с `unknown` без judge и version-aware EvidenceRAG prototype, а также три реализуемые абляции.

Оригиналы и текст хранятся в одной SQLite для атомарного каскадного удаления. До 20 файлов/40 МБ на пространство, всего до 400 МБ оригиналов. База с индексом и свободными страницами может быть больше этой суммы; нужен мониторинг свободного места. Рабочие пространства живут 24 часа, очистка при запуске и раз в минуту. Это не шифрованный сейф.

Версия — строка владельца, дата — дата применимости, а не время загрузки. `as_of` выбирает max(date) в каждой группе; модель предполагает полные снимки редакций и не реализует наследование отдельных поправок. Разные literal поля между редакциями не называются конфликтом; same-edition расхождение помечается только при установленной общей редакции, иначе applicability остаётся неизвестной. `evidence_id` детерминирован по content/position и не доказывает достоверность источника.

Судья достаточности предусмотрен как внутренний callback интерфейс, но в продукте и воспроизводимом run-004 не подключён. Lexical coverage используется для диагностики поиска, а не как семантическая достаточность. Нет энтейлмента, свободного генератора или faithfulness-оценщика.

Клиентская навигация: apps/web/src/navigation.ts задаёт четыре адреса. App.svelte использует реальные ссылки и History API с обработкой popstate; FastAPI возвращает entry HTML для /documents, /compare и /method. Статические файлы и неизвестные URL сохраняют обычное поведение, произвольного catch-all на API нет.
