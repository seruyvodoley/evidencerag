# Метод исследования

1. Зафиксировать корпус, лицензию, SHA-256, применимость версий и независимые семьи документов.
2. Разметить необходимое множество источников, эталонный ответ, достаточность, конфликт и причины отказа. Независимая двойная разметка и adjudication обязательны для будущего реального корпуса; синтетические fixtures размечены автором генератора и не отвечают этому требованию.
3. Делить по семьям документов. Сейчас train=device, dev=api, test=service/conflict/bundle; это только 63 маленьких случая, не статистически достаточная выборка. Порогов, подобранных по test, нет.
4. Сравнить fixed5, fixed10, adaptive и versioned при одинаковых лимитах. Отдельно четыре абляции: лексической остановки, версий, сигналов конфликтов и адаптации.
5. Сохранять конфигурацию, версии Python/SQLite, commit, хеши входов, реальные document/chunk IDs, запросы, трассы, задержки и метрики. CLI запрещает перезапись каталогов. Seed=0; поиск детерминированный, время и криптографические document IDs меняются.
6. Исследовать selective risk/coverage, recall по применимым источникам, ошибки дат, стоимость контекста и latency. Не приравнивать долю совпавших слов к вероятности правильного ответа.

Статистическая программа для статьи: парный bootstrap по семьям, несколько независимых авторов корпусов, заранее заданный тестовый протокол, анализ ошибок и отрицательных результатов. Wilson CI в текущем JSON — иллюстрация для accuracy, без поправки на зависимость вопросов; не использовать как доказательство значимости.

Контроль источников: нынешние эталоны заданы точными строками с фильтром группы/версии. Датированная разметка в fixtures неполна, поэтому date_scope без required не участвует в evidence recall. Исправление датированной эталонной разметки — задача до научной публикации.
