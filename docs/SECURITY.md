# Безопасность и приватность

Модель угроз: недоверенные файлы, чужие сеансы, инъекции в запрос/документ, XSS, CSRF, архивные бомбы и исчерпание ресурсов. Разбор не исполняет инструкции или макросы. На сервере нет инструментов агента, доступных документам.

Сеанс: 256 случайных бит в HttpOnly/SameSite=Strict cookie, Secure для HTTPS. В БД хранится SHA-256 токена; токен не размещается в URL или frontend storage. Каждое чтение, скачивание, удаление, поиск и сравнение требует workspace. Это bearer capability: кража cookie даёт доступ. Аккаунтов, восстановления и совместного доступа нет. Администратор VPS технически может читать БД; encryption-at-rest не реализовано.

TTL 24 часа, фоновое удаление каждые 60 секунд, истёкший cookie немедленно перестаёт давать доступ. Каскадное удаление originals/chunks, триггеры FTS, SQLite secure_delete и FTS5 secure-delete. WAL checkpoint при очистке. Не обещается физическое уничтожение копий на SSD/в резервных копиях. Приватные документы не включать в долгосрочные backup.

Upload: до 10 МБ, общий запрос до 10.1 МБ (ограничение потока до multipart), allowlist расширений и проверка фактического формата, ZIP до 1000 элементов/25 МБ распакованных данных, до 300 PDF-страниц и 180000 символов. Один парсер за раз, отдельный процесс 15 секунд; Linux RLIMIT CPU/AS. Original только attachment octet-stream; пользовательский HTML/PDF не исполняется inline. Файловые пути не берутся от клиента.

Защита UI: Svelte escaping, отсутствие raw HTML, CSP self с object-src none/frame-ancestors none, nosniff/no-referrer/no-store, запрет cross-site Origin/Sec-Fetch-Site для мутаций, SQL placeholders и очистка FTS-терминов. Ошибки парсера и неожиданные ошибки не печатают текст документов. Uvicorn access log отключён. Reverse proxy тоже не должен писать cookie, тела запросов или IP посетителей.

Ограничение: 90 мутаций/минуту с адреса соединения и 1000 глобально, 1000 пространств, 20 файлов/40 МБ на пространство, 400 МБ originals суммарно. За localhost proxy все клиенты делят один bucket: текущий лимит подходит только небольшому pilot. Публичный production потребует продуманного доверия proxy и ограничения запросов на его уровне. Нужен мониторинг диска: индекс/свободные страницы не входят в лимит originals.

LLM выключена и публичного endpoint нет. Адаптер требует согласия, ключа, положительных бюджетов и ограничивает вызовы/контекст/выход. Проверяет действительность ID и точное вхождение цитаты, разрешает только дословные выдержки. Это не полная защита от смысловой манипуляции prompt injection. Резервирование расходов в памяти не заменяет hard cap провайдера и не переживает перезапуск; для публичного LLM-режима нужны постоянный ledger, верифицированные тарифы, отдельный entailment-оценщик и аудит. Реальных API-вызовов не было.

Аудит зависимостей: experiments/python-audit.json без известных находок; npm production audit без находок. Полный npm audit: 3 low в dev-цепочке deepmerge / Svelte Vite inspector, исправление upstream недоступно. В production отдаётся static bundle без dev-server. Это не сертификат отсутствия уязвимостей. Dockerfile/Compose подготовлены, локально Docker отсутствует и образ не проверен; VPS использует systemd.
